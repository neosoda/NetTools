Présentation

01

NetTools est une application de gestion réseau destinée aux opérations courantes d’administration : découverte SNMP, inventaire, sauvegarde de configurations, audit, comparaison de fichiers et exécution de commandes.

Elle fonctionne comme une application Windows autonome. Les données sont stockées localement et les secrets sont chiffrés avant d’être enregistrés.

Découvrir

Scanner une plage IP, interroger les équipements en SNMP et récupérer les informations utiles.

Sauvegarder

Se connecter en SSH aux équipements et archiver les configurations running ou startup.

Contrôler

Auditer les configurations, identifier les écarts et préparer les corrections.

Installation et premier démarrage

02

Prérequis

Poste Windows 10 ou Windows 11 en 64 bits. WebView2 doit être présent sur la machine.

Données locales

Au premier lancement, NetTools crée son espace de travail dans %APPDATA%\NetTools\.

Télécharger l’exécutable

Récupérer NetTools.exe depuis la source de distribution prévue.

Lancer l’application

Exécuter le fichier. Si Windows affiche un avertissement, vérifier la provenance du fichier avant de continuer.

Configurer les accès

Créer au moins un credential SNMP et/ou SSH avant de lancer les premiers scans et backups.

À retenir : un scan SNMP sans credential valide donnera un résultat vide ou incomplet. Commencer par les credentials évite de perdre du temps.

Interface

03

L’interface est organisée autour d’une barre latérale et d’une zone principale. La barre latérale permet de changer de module et de sélectionner le credential global utilisé par défaut.

Barre latérale

Accès aux modules : scan, inventaire, backups, audit, diff, playbooks, planificateur, topologie, journaux et paramètres.

Zone principale

Affiche les formulaires, résultats, tableaux, historiques et actions du module en cours.

Credential global : lorsqu’aucun credential spécifique n’est affecté à un équipement, NetTools utilise celui sélectionné dans la barre latérale.

Credentials

04

Les credentials regroupent les informations nécessaires aux connexions SNMP et SSH. Les mots de passe, clés privées et secrets SNMP sont chiffrés avant stockage.

Ouvrir les paramètres

Aller dans Paramètres, puis dans l’onglet Credentials.

Ajouter un accès

Créer une entrée avec les informations SSH, SNMP ou les deux selon l’usage prévu.

Sélectionner le credential

Utiliser le credential comme accès global ou l’associer directement à un équipement de l’inventaire.

Modifier un credential existant

Lors de la modification, les champs sensibles peuvent rester inchangés. Ne renseigner un nouveau secret que si l’on souhaite réellement le remplacer.

Supprimer un credential

La suppression retire l’entrée de NetTools. Si le credential supprimé était sélectionné comme accès global, il faudra en choisir un autre.

Inventaire des équipements

05

L’inventaire contient les équipements connus de NetTools. Il peut être alimenté manuellement ou importé depuis un fichier JSON.

Ajouter un équipement

Inventaire

Renseigner l’adresse IP, le nom, le fabricant et les informations utiles. Associer un credential si l’équipement ne doit pas utiliser l’accès global.

Importer / exporter

Inventaire · JSON

Exporter l’inventaire pour le conserver, le déplacer ou le réimporter plus tard. L’import permet de reconstruire rapidement une base propre.

Test de connexion : l’icône de test SSH permet de vérifier rapidement si l’équipement accepte la connexion avec le credential sélectionné.

Découverte réseau

06

Le scanner interroge les équipements en SNMP afin de récupérer les informations principales : identité, fabricant, description système et métadonnées disponibles.

ModeUsageExemple
SwitchesScan rapide sur les IP courantes d’équipements réseau.10.0.1
CompletScan de tout un réseau en /24.10.0.1
CIDRScan d’une plage personnalisée.10.0.0.0/22
ManuelScan d’une liste d’adresses précises.10.0.1.1, 10.0.1.2

Workers

Le réglage par défaut convient dans la majorité des cas. Monter progressivement si le réseau et les équipements suivent.

Timeout

Augmenter le délai si les liens sont lents ou si certains équipements répondent tardivement.

Résultat vide : vérifier d’abord la communauté SNMP, la version utilisée, le port UDP/161 et la portée réseau depuis le poste.

Sauvegardes SSH

07

Le module Backups se connecte aux équipements en SSH et récupère les configurations. Il peut travailler sur une sélection manuelle ou sur les résultats du dernier scan.

Choisir le type de configuration

Sélectionner Running pour la configuration active ou Startup pour la configuration sauvegardée.

Sélectionner les cibles

Choisir les équipements à traiter, puis vérifier le credential utilisé.

Lancer la sauvegarde

Suivre la progression et consulter l’historique une fois l’opération terminée.

Historique des sauvegardes

L’historique permet de relire une configuration sauvegardée et d’ouvrir une console SSH directe sur l’équipement si une vérification manuelle est nécessaire.

Audit de conformité

08

Le module Audit contrôle les configurations par rapport à des règles prédéfinies. Chaque résultat indique si la règle est respectée et propose, lorsque c’est possible, une remédiation.

Sélectionner

Choisir les équipements à contrôler depuis le dernier scan ou une liste manuelle.

Auditer

Cocher les règles à appliquer puis lancer l’analyse.

Corriger

Copier les commandes de remédiation après validation humaine.

Important : une commande de remédiation doit être relue avant exécution. Ne pas appliquer automatiquement sur un équipement de production sans contrôle.

Comparateur de configurations

09

Le comparateur sert à analyser deux versions d’une configuration : avant/après maintenance, running/startup, ou deux sauvegardes issues d’équipements proches.

Vue côte à côte

Diff

Comparer deux fichiers avec un affichage synchronisé et des lignes colorées selon le type d’écart.

Filtres

Diff · Options

Ignorer la casse, les espaces ou appliquer des expressions régulières pour réduire le bruit.

Playbooks SSH

10

Les playbooks permettent d’exécuter une suite de commandes sur un ou plusieurs équipements. Le format utilisé est YAML.

Exemple YAML
name: Vérification Sécurité
timeout: 120s
steps:
  - name: Version
    command: show version
  - name: SSH Status
    command: show ip ssh
    expect: SSH Enabled

Créer ou importer

Préparer le fichier YAML depuis le module Playbooks.

Choisir les équipements

Sélectionner les cibles concernées par les commandes.

Contrôler la sortie

Lire le terminal temps réel et le résumé d’exécution.

11

Topologie et journaux

12

Topologie

Topologie

Affiche les équipements sous forme graphique avec un code visuel par fabricant et des indications utiles comme le PoE.

Journaux

Paramètres

13

Les paramètres regroupent les options générales de l’application.

Affichage

Choix du thème et de la langue de l’interface.

Exécution

Réglage du nombre de workers pour les opérations parallélisées.

Sauvegardes

Choix du dossier de destination des backups. Un dossier réseau ou NAS est recommandé si les sauvegardes doivent être centralisées.

Credentials

Création, modification et suppression des accès SNMP/SSH.

Procédures courantes

14

Audit hebdomadaire

  1. Lancer un scan réseau pour actualiser les équipements.
  2. Vérifier l’inventaire et les credentials associés.
  3. Créer une tâche d’audit planifiée.
  4. Relire les résultats et traiter les écarts prioritaires.

Maintenance réseau

  1. Faire un backup avant intervention.
  2. Effectuer la modification sur l’équipement.
  3. Faire un backup après intervention.
  4. Comparer les deux versions dans le module Diff.

Bonne pratique : toujours conserver un état avant/après pour les opérations sensibles. Le comparateur rend les écarts visibles rapidement.

Dépannage

15
SymptômeContrôles à effectuer
Scan videVérifier la communauté SNMP, la version SNMP, le port UDP/161, le timeout et la connectivité réseau.
Backup incompletVérifier le vendor détecté, tester la connexion SSH et comparer avec une session terminal manuelle.
Erreur DB lockedFermer les autres instances de NetTools puis relancer l’application.
SSH refusedContrôler le port SSH, les droits du compte, les ACL et l’état du service SSH sur l’équipement.
Où trouver les logs ?

Les logs sont disponibles dans %APPDATA%\NetTools\logs\. Le fichier mensuel suit le format nettools-YYYY-MM.log.
